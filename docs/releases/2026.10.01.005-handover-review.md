## Targeted changes

### Database and offboarding worker

- [Scheduled handover migration](../../supabase/migrations/20261001215508_scheduled_handover_005.sql): private schedule/audit/checkpoint/outbox tables, cutoff-aware account and recipient functions, restrictive authorization policies, capability additions, cron dispatcher, and bounded worker RPCs.
- [Assignment transfer migration](../../supabase/migrations/20261001222228_handover_assignment_transfer_005.sql): exact-token replacement, bounded live assignment transfers, future normalization for the identified inventory/rule fields, co-assignee preservation, and per-record audit entries. Shear transfer changes both username and profile ID; historical source-assignee fields stay intact.
- [Worker entrypoint](../../supabase/functions/scheduled-offboarding/index.ts) and [handler](../../supabase/functions/scheduled-offboarding/handler.ts): exact service credential, Auth ban, bounded network timeouts, checkpoint reconciliation, and Dylan-only notifications.
- [Session checks](../../supabase/functions/_shared/app-auth.ts): live account checks for native and legacy sessions. `app-api`, `auth-admin`, and `inventory-assistant` use the updated shared boundary.

### Email and push

- [Code.gs](../../Code.gs): one final-delivery resolver rebuilds To/CC/BCC for GmailApp and raw Gmail API messages, including stored threads, queued work, and retries. Receipts use the resolved recipients so a departed required recipient cannot cause a resend loop.
- [Operational routing](../../supabase/functions/_shared/operational-routing.ts) and [push sender](../../supabase/functions/send-push-alert/index.ts): resolve configured and payload recipients at send time; deduplicate overlap; recheck each push batch; require the actual service credential for administrative notices.
- Before cutoff, Kayla routes include Nelly. After cutoff, they resolve to Nelly. Resolver failures stop delivery rather than reuse stale recipients. A message already handed to the email/push provider cannot be recalled.
- Approval links verify the actual signed-in visitor, never the Apps Script deployment owner's identity. If Google does not expose the visitor's identity, the page directs the user to approve in the authenticated app.
- This changes application-managed routing only. It does not alter company email accounts or external Microsoft/Google groups.

### Que archive

- [Native Request UI](../../index.html): both swipe directions, confirmation with request identity, accessible Archive controls, keyboard access, optimistic queue updates, Undo, and a paged Archived view with Restore.
- [Archive migration](../../supabase/migrations/20261001215511_request_archive_005.sql): service-only command ledger and transactional archive/restore RPCs. The verified session supplies the actor; the existing `can_archive` capability is enforced through its database predicate. Completed requests retain their existing protected handling; this gesture targets pending Que requests.
- [app-api](../../supabase/functions/app-api/index.ts): authenticated `request_archive` action with `archive`, `restore`, or bounded `list` operations. It preserves SQLSTATE/HTTP status and does not accept a client-supplied actor.
- Archive changes visibility only. It neither deletes requests nor changes completion fields; the completion-reconciliation trigger is suppressed for this operation. Existing server history and its snapshots are left untouched; the separate command ledger records archive/restore events. The browser's hard-delete fallback and completion-email invocation have been removed.
- Pending commands are identity-scoped and retain their idempotency key and attempt count. Transient retries stop after three attempts; permission errors are terminal. Rejected commands restore the card and show an error.
