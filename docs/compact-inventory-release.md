# Compact inventory loading — release 2

Target shell: `V2026.09.10.02`. Publish only after release 1 is live and this exact commit passes its independent candidate checks.

## Boundary

The native revision-verified master adapter reads all authorized physical rows using the versioned 161-field list contract. Short field aliases reduce repeated JSON key bytes without changing values. Every alias and identity is validated; there is no truncated first-page result or wildcard fallback. Account, permission, source revision and query identity remain part of cache validation.

List completeness is separate from full exact-row completeness. Editors obtain full rows by exact IDs through the existing authenticated read boundary, behind the same before/after revision checks. These full snapshots remain separate from the list and from editable drafts. Reclass and Sales Office exports obtain their necessary complete scopes; missing or ambiguous identities fail with retry guidance instead of filling unknown fields with zeroes or blanks.

Decoding, formatting, search fields and master lookup Maps are prepared in detached, cancellable chunks before an atomic publish. Existing season-assignment and inheritance operations stay in their current commit order; this release does not claim every synchronous application transform has been removed.

Only the explicitly owned compact master adapter transfers its detached result to the coordinator. Canonical, mutable UI, and persistence graphs remain separate; copies yield between bounded batches and are prepared before the final permission/revision check. Generic adapters still capture their potentially mutable stage results immediately. Navigation reuses same-identity reads; account/auth/query changes discard them. Supported selectable Drive/AV column fields remain in the projection; unsupported manually authored persisted filter keys are not expanded into a new full-master download workflow.

## Measurements and acceptance

The same full-schema synthetic 128-row fixture measures 616,168 bytes for full objects and 263,528 bytes for the aliased list: a 57.231% reduction. A bounded read-only production aggregate measured 53.491% reduction for the same 128 source rows. These are JSON body representations, not promises about compressed production egress or future data distributions. See `inventory-list-projection.md` for the field contract and limits.

Contract, detached staging and exact-detail unit tests exercise missing fields/rows, duplicate identities, revision/permission fences, account changes and cancellation. Compiled browser, release regression, exact-live and hosted health results must be recorded before marking this release complete. No migration, permission change, import rule, business-data rewrite or email change belongs to this release.

Before the final R1 merge, the focused contract/copy/staging/fixture/coordinator union passed 90/90; the independent detail/cache-integration union passed 100/100. A synthetic 10,000-row Node benchmark of the real coordinator yielded 285 times on cold loading and 286 on warm loading, with p95 synchronous segments approximately 8 ms. The final post-metadata reference publication measured 0.30/0.23 ms, replacing the earlier 2.72–2.75-second contiguous clone chain. Warm loading made zero row downloads. Total Node wall time was approximately 4.25 seconds, not an overall loading-time improvement claim: pacing, network, browser rendering, IndexedDB serialization, and existing assignment transforms are separate costs. At 1,000 rows the same cold/warm benchmark took 411/428 ms. Browser acceptance and all exact-commit hosted gates remain required.

The freshly compiled `4d382830` browser matrix passed 79/80 cases across Chromium, Firefox, WebKit, Android and iPhone. The sole failure sampled an instantaneous verification flag during an independent foreground metadata recheck, after verified master data had already appeared and while an unrelated credit request remained held. The test now polls verification without releasing that held request, then asserts the gate remains closed. The corrected case passed all five profiles (5/5, 21.8 seconds). This is a validation union, not an assertion that the original 80-case run was entirely green; its failure remains in `artifacts/compact-final-80`, and the corrected results remain in `artifacts/compact-badge-verification-5/results.json`.

All five warm cases displayed saved inventory after access resolution in 287.5 / 348 / 459 / 229 / 409 ms respectively, with zero full inventory downloads and zero inventory body bytes. All five full-schema 128-row parity cases retained list/filter/count parity and measured the same 57.231% raw JSON reduction. Their cold readiness after access resolution was 1,033 / 1,342 / 3,925 / 1,196 / 3,398 ms; these are retained diagnostic measurements, not sub-second first-download claims. Chromium and Android reported two long tasks each (maximum 66 / 55 ms); unsupported long-task instrumentation on other engines is recorded as unavailable, not zero.

The final compiled AV Blanks suite passed 10/10 with strict 161-field list and 213-field exact-row fixture checks. The focused protected-photo union passed 24/24: 18 Chromium/Firefox/WebKit cases and six Android cases covering photo-only saves, save retry without re-upload, multiple photos with notes, delayed detail hydration preserving drafts, and second-client persistence. No application changes were needed after those checks. The shared Chromium bootstrap test now polls explicit page-owned terminal state instead of exporting an asynchronous return promise through CDP; failures still stop with diagnostics. Full exact-commit hosted validation and publication remain pending.
